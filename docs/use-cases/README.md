# Supported role walkthroughs

**Audience:** Employees, administrators and implementation partners. **Implementation status:** Implemented engineering role packages; deployment/UI limitations apply.

These five roles are confirmed in the pinned catalog at `9e7ec4eba0eeddb0fdb86c18740a1c1a610146a4`. They share the same runtime, action gateway and execution services; there is no separately deployed QA-only kernel. Prepare organization-managed credentials, V2 issuance and generic runtime before attempting these guided workflows.

- [qa-engineer 1.2.0](qa-engineer.md)
- [frontend-engineer 1.1.0](frontend-engineer.md)
- [backend-engineer 1.0.0](backend-engineer.md)
- [code-reviewer 1.0.0](code-reviewer.md)
- [test-automation-engineer 1.0.0](test-automation-engineer.md)

Latest versions are used for these walkthroughs. QA 1.1.0 and Frontend 1.0.0 remain immutable registered versions; they are not marked deprecated without a source decision. DevOps, product manager, sales, HR and finance agents are not shipped role packages, so no invented end-to-end guides are supplied.

These examples explain participating components, policy defaults, expected artifacts and failure boundaries. They do not assert a fixed completion time or guaranteed model outcome. Model-driven workflow guidance is distinct from a deterministic scheduler. Use [implementation status](../reference/implementation-status.md), [QA strategy](../qa/test-strategy.md) and [pilot readiness](../qa/pilot-readiness.md) to assess deployment evidence.
